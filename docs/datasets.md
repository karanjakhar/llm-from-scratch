# Datasets — verified availability and sizes

**Domain decision: Python code + ~15% high-quality English.** See
`docs/domain_choice.md` for why.

Everything below was checked against the HuggingFace API on **2026-10-14**.
Numbers come from `datasets-server.huggingface.co`, not from memory. Re-verify
before a long download; dataset repos get gated, renamed, and restructured.

Total download for the full pipeline: **under 10 GB**, against 98 GB free.
Nothing requires a token or an access request.

### Token budget

5.0 GB of Python at roughly 2.8 bytes/token (our 8192 vocab; measure it in
Stage 01) ≈ **1.8B tokens of code**. Add ~0.3B tokens of English for the 85/15
mix ≈ **2.1B tokens total**, which is Chinchilla-optimal for about **105M
parameters**. That lines up with the 125M ceiling from the compute table, with
one caveat: hitting 2.5B tokens means ~1.2 epochs over the code. Repeating data
up to ~4 epochs costs very little, so this is fine — but it is a real
constraint to state rather than discover.

## Traps found while verifying — read before downloading anything

### `HuggingFaceTB/python-edu` ships no code

This is the obvious first choice (it is the Python half of the SmolLM corpus,
quality-scored, deduplicated) and it **does not contain source code**. First
trap: it is not its own repo — it is a *config* of
`HuggingFaceTB/smollm-corpus`. Second and worse, its schema is:

```
blob_id, repo_name, path, length_bytes, score, int_score
```

Metadata only. To get the actual code you fetch every file from Software
Heritage's S3 bucket by `blob_id`, which needs AWS credentials and 477k+ S3
requests. Technically possible, a bad first step for this project.

Same structure applies to `fineweb-edu-dedup` and `cosmopedia-v2` configs —
check the schema, not the dataset card's prose.

### `bigcode/*` is gated

`bigcode/starcoderdata`, `bigcode/the-stack-v2`, and even
`bigcode/the-stack-smol` all report `gated: auto` — they need terms accepted
and an HF token. They are better-filtered than codeparrot-clean and are the
right upgrade later, but they are not a zero-friction start.
`bigcode/humanevalpack` is **not** gated, so it is available for eval.

### Licensing

`codeparrot-clean` carries a `license` column per file. Filter to permissive
licenses (`apache-2.0`, `mit`, `bsd-*`) in Stage 02 rather than training on
everything. Cheap to do, and it is the difference between a project you can
publish and one you cannot. The `autogenerated` column is also worth filtering
on — generated code is highly repetitive and inflates apparent quality.

## Scale-up path, if 5 GB turns out to be the binding constraint

1. `codeparrot/github-code-clean` — ungated, multi-language, far larger.
   Filter to `language == "Python"`.
2. `bigcode/the-stack-v2` — accept the terms, get a token. Best filtering and
   dedup available, and what real code models actually use.
3. More `fineweb-edu`. `sample-10BT` alone holds 10B tokens; we use ~3% of it.

## Reproducibility

Every download gets pinned in Stage 02's `prepare.py`: dataset id, config,
revision hash, and the filter predicates. "I trained on codeparrot-clean" is
not reproducible. The revision hash is.
